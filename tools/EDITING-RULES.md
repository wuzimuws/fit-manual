# 编辑本项目的注意事项

## 改完之后跑这两条

```bash
bash tools/check.sh          # 体检
python3 tools/build_web.py   # 重建网页
```

## ⚠️ check.sh 查不出的那一类错

`check.sh` 能查出「引用的条号**不存在**」，但**查不出「引用的条号存在、却不是想说那条」**。

**插条 / 删条 / 移动条 会让后面所有条号整体位移**，正文里所有 `见第 N 条`、`见 XX 节第 N 条` 会一起指错，而校验仍然通过。

真实案例：作者把「心理障碍」从第 6 条提到第 1 条并删掉原第 1 条之后——
- 结语里「01 节第 13 条」（修心）实际变成了第 12 条
- 第 1 条内部「见第 12 条」（别人盯着我看）实际变成了第 11 条
- `check.sh` 全部通过

**所以插删移动之后，必须手工核一遍所有条号引用：**

```bash
grep -rn "第 [0-9]* 条" book/ 前言.md 结语.md README.md 附录-参考书目.md
```

## 不要做的事

- **不要整文件覆写**（会冲掉手改内容）——只用逐句替换
- **不要 `git add -A`**——只提交实际改过的文件
- **写文件前先 `git status`**——有未提交改动就先停下来确认
